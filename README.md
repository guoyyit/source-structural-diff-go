# source-structural-diff-go

源码结构差异比对与审查基线服务。对 Go 源码树做**声明级**结构差异分析，
注释、空白与格式化变化不会影响比对结论；支持以增量方式维护已提交基线，
并对任意两个基线（或工作区与基线）输出稳定、可复现的差异报告。

## 构建与测试

```sh
go build ./...
go test ./...
```

## 使用方式

```sh
# 提交基线（扫描 root 下的 Go 源码树，原子提交，输出基线 ID）
ssdiff commit --store .ssdiff <root>

# 列出已提交基线（按提交时间从旧到新）
ssdiff list --store .ssdiff

# 对比两个已提交基线
ssdiff diff --store .ssdiff <oldID> <newID> [--format text|json]

# 对比基线与工作区（baseID 传 "" 表示与空树对比）
ssdiff diff-workspace --store .ssdiff <baseID> <root> [--format text|json]
```

提交过程中的进度（已处理文件数、最慢文件）输出到 stderr；报告输出到
stdout，按**文件路径 → 符号 ID → 类别**稳定排序。同一对版本重复比对，
输出逐条一致。

## 分类语义

比对以"声明"为粒度（顶层 `func`/`method`/`type`/`var`/`const`），每条
变更属于以下类别之一：

| 类别 | 含义 |
| --- | --- |
| `unchanged` | 同一文件同一符号，结构指纹完全一致（注释/空白/格式化变化算此类） |
| `modified` | 同一文件同一符号，签名或函数体发生了语义变化 |
| `added` | 新树中新增、且没有任何旧声明能与之匹配 |
| `deleted` | 旧树中删除、且没有任何新声明能与之匹配 |
| `renamed` | 同一文件内符号改名，结构相似性证据达到采纳阈值 |
| `moved` | 符号跨文件移动（可同时伴随改名），证据达到采纳阈值 |

### 结构指纹与格式化不变性

解析时不读取注释；每个声明被规范化为与位置无关的 token 流（冗余括号、
多余分号等格式化噪音被忽略），再对其做哈希。因此重新格式化、增删注释、
调整空行都不会改变任何哈希，也不会改变比对结论。

### 重命名 / 移动判定：证据与置信度

改名与移动**不**依据名称是否相同，而是依据结构相似性证据加权求和：

| 证据 | 权重 |
| --- | --- |
| `identical-body` 规范化函数体完全一致 | 0.55 |
| `body-similarity` 函数体 token shingle 的 Jaccard 相似度 | 0.55 × 相似度 |
| `identical-signature` 签名（参数/返回值/接收者类型，形参名除外）一致 | 0.30 |
| `identical-name` / `name-similarity` 名称相同或编辑距离相似 | 0.15（× 相似度） |

阈值（`diff.Options`，可用默认值）：

- **采纳阈值 0.75**：置信度 ≥ 0.75 才分类为 `renamed`/`moved`。
- **候选阈值 0.35**：0.35 ≤ 置信度 < 0.75 的配对报告为**候选匹配**
  （`candidate: true`），不会被静默错分，也不会被拆成 add/delete。
- 低于候选阈值的配对按 `added` + `deleted` 处理。

防误判设计：

- 结构无关的同名符号只有名称证据（0.15），远低于候选阈值。
- 微小声明（如空函数，AST 节点数 < 10）的"函数体一致"证据会按 0.3 系数
  衰减——空函数体雷同是巧合而非改名证据。
- 候选配对采用按置信度降序的确定性贪心匹配，平局按稳定键排序，保证
  结果可复现。

每条 `renamed`/`moved` 变更都附带 `evidence` 列表（证据类型、权重、
说明）与 `confidence`，见报告输出。

## 基线：提交、增量与恢复

- **原子提交**：基线先写入 `tmp/` 再 fsync + 原子 rename 到
  `baselines/`，任何时刻查询只能看到完整提交的基线，不存在半提交状态。
- **崩溃恢复**：服务启动（`Open`）时清理 `tmp/` 下的未完成提交残留；
  已提交基线从磁盘重新加载后可继续使用。
- **内容寻址 ID**：基线 ID 由全树内容哈希派生，同一内容重复提交得到
  同一 ID；增量提交与全量重算产生的基线完全一致（有测试保证）。
- **增量维护**：提交新基线时与最新基线逐文件比对内容哈希，未变化的
  文件直接复用已解析结果，不重复解析；只有新增/修改的文件进入解析
  流水线。
- **并发与隔离**：提交与查询可并发进行；查询持有的是不可变基线快照，
  提交发布新基线不影响进行中的查询。
- **有界资源**：解析在固定大小的 worker 池（CPU 核数）上并行执行，
  文件内容边读边释放；`context` 取消/超时会使提交失败且不留部分基线。

## 代码结构

| 包 | 职责 |
| --- | --- |
| `internal/decl` | Go 源码解析为声明模型 + 位置无关规范化指纹 |
| `internal/diff` | 声明级差异分类、相似性证据与置信度 |
| `internal/baseline` | 基线存储：原子提交、崩溃恢复、增量构建 |
| `internal/service` | 门面：并行扫描、取消、进度、并发安全查询 |
| `internal/report` | 稳定排序的文本 / JSON 报告 |
| `cmd/ssdiff` | 命令行入口 |
